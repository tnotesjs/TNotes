### 1.1 验收阶段与终端优先级

1. **第一阶段：桌面端编辑交互。** 优先完成编辑体验与编辑交互细节，并以幕布实际行为为验收基准；重点包括节点编辑、拖拽、快捷键、连续节点选中，以及从剪贴板粘贴截图并形成图片节点。
2. **第二阶段：移动端 / 小屏适配。** 桌面端编辑交互验收通过后再开始，不应在第一阶段分散实现重点。
3. **阶段提醒：** 桌面端编辑交互验收通过时，Agent 必须主动提醒用户开始移动端 / 小屏适配工作。

**分层边界：** 当前阶段讨论的是编辑器本身。目录授权、作品文件结构、直接保存、`assets/`、PWA 和草稿恢复均属于 `mindmap-web` 应用外壳，不属于编辑器交互验收；其中工作区和目录文件管理可以暂不实现，不能因此偏离幕布编辑体验对齐。截图粘贴虽然涉及图片数据落地，但属于必须解决的核心编辑能力。

初版不以节点样式丰富度为重点；背景色、主题样式仍后置。验收新增要求中的语义行内格式（粗体、斜体、下划线、删除线、高亮、行内代码和链接）已经实现，但不扩展为完整样式系统。

当前兼容性基线只考虑**最新版 Google Chrome**。Safari、Firefox、Edge、旧版 Chrome 以及其它浏览器暂不纳入开发与验收范围；后续有明确需求时再补兼容策略。

部署形态确定为**纯静态前端应用**，未来发布到 GitHub Pages。不建设账号体系、云同步、服务端存储或后端 API；文档解析、编辑、草稿恢复、工作区目录访问和资源处理均在用户浏览器本地完成。

### 1.2 Markdown 合法性与非法源码处理（已实现，2026-08-18）

- `*.tn-mindmap.md` 是专用数据格式；合法内容必须包含一个 H1 根节点，**无 H1 属于非法格式**，不再以文件名创建虚拟根。
- H1 后只允许一个无序列表块与空行；列表标记和缩进可以宽容解析，但 frontmatter、普通段落、表格、第二个 H1 等无法无损表示为节点树的内容均视为非法。
- 原始 Markdown 与最后一次合法解析得到的脑图状态需要分开保存，源码不得被自动规范化覆盖。
- 检测到非法格式时，只允许停留在可编辑的源码视图；大纲和脑图入口禁用，并展示具体错误及行号。
- 修复为合法格式后恢复大纲和脑图入口，但不强制自动切换视图。
- 非法状态仍应允许导出原始源码，避免用户无法取回数据。
- 已落盘作品进入非法状态后暂停自动写盘，并显示“格式错误，尚未保存”等明确状态；用户主动保存时弹出风险确认，确认后允许把原始非法源码直接写入 `.tn-mindmap.md`。
- 已强制写入的非法作品再次打开时仍只允许进入源码视图，直至修复合法。

实现位置：`@tnotesjs/mindmap-core/markdown` 提供严格诊断；`MindmapSession` 分离原始源码与最后合法文档树；`MarkdownView.vue` 和 `App.vue` 负责错误定位、视图锁定、恢复入口与非法保存确认。已用真实页面自动回归“无 H1 锁定 → 修复 H1 恢复入口”。

### 1.3 截图粘贴与最小本地作品生命周期（核心链路已实现，2026-08-18）

- 用户首次进入时处于“未落盘作品”状态，以合法的默认 Markdown（如 `# 未命名`）开始；源码、大纲、脑图三种视图均可直接编辑，不预先请求文件系统权限。
- 未落盘的文字草稿保存在 IndexedDB，避免刷新或意外关闭后丢失。
- 以下任一动作触发“创建本地作品”：
  1. 首次从剪贴板粘贴截图；
  2. 用户主动执行“保存为本地作品”。
- 创建流程：用户输入作品名称并选择一个已存在的本地父目录；Web 应用在该父目录下创建 `<作品名>/`，并生成 `<作品名>.tn-mindmap.md` 与 `assets/`。
- 首次粘贴截图时先暂存图片 Blob；只有作品目录、图片文件和 Markdown 均成功写入后，才提交图片节点。用户取消或写入失败时，不插入图片，也不影响已有文字内容。
- 新建前检查同名作品目录，默认不覆盖已有目录；目录结构错误或写入失败时展示明确错误。
- 打开已有本地作品时选择作品目录并校验同名 `.tn-mindmap.md`，不依赖单文件路径反查父目录。
- 作品落盘后，文字与结构变更采用防抖自动保存，不要求用户反复手动保存；界面展示“保存中 / 已保存 / 保存失败”状态。
- 编辑器核心只发出图片 Blob 写入请求；Web 适配器使用 File System Access API，VS Code 适配器使用扩展文件系统能力，只读的 `tnotesjs/core` 不提供图片写入实现。
- 删除图片节点或撤销截图粘贴时不立即删除 `assets/` 中的实体文件，避免破坏撤销 / 重做、共享引用和异常恢复；失去引用的文件视为孤立资源。
- 截图粘贴与保存流程稳定后，再提供应用层的“未引用资源”入口：展示缩略图、文件名、大小、修改时间和引用次数，允许重新插入节点或多选确认删除；默认只扫描当前作品的 `assets/`，绝不自动清理。

当前实现位置：

- `src/app/localProject.ts`：创建 / 打开严格作品目录、主文件与 `assets/` 读写、拒绝同名覆盖。
- `src/app/imagePaste.ts`：源码视图中的整节点图片插入策略。
- `MindmapSession.prepareImageInsertion`：先生成待写 Markdown，写盘成功后再原子提交节点，且可撤销。
- `OutlineView` / `CanvasEditor` / `MarkdownView`：识别剪贴板图片 Blob 并上抛应用层。
- `App.vue`：首次粘贴触发作品创建、对象 URL 资源解析、500ms 自动保存、保存状态和非法源码显式保存。

尚未实现：IndexedDB 文字草稿 / 目录句柄恢复、孤立资源预览管理、外部文件冲突检测；这些不阻塞当前截图核心链路验收。

### 1.4 Web 应用层：多作品工作区管理（远期设想，当前非必需）

- 通过浏览器目录授权能力选择一个工作区根目录。工作区只枚举**一级子目录**，不做任意深度递归扫描；每个一级子目录代表一件可独立搬运的作品。
- 新建作品即在工作区下新建一个作品子目录；作品 Markdown 与资源共同放在该目录内，例如：

  ```text
  workspace/
  ├── project-1/
  │   ├── project-1.tn-mindmap.md
  │   └── assets/
  └── project-2/
      ├── project-2.tn-mindmap.md
      └── assets/
  ```

- 每个作品目录必须**恰好包含一个**脑图主文件，并且文件基名必须与作品目录名完全一致，即 `<作品名>/<作品名>.tn-mindmap.md`。缺少同名主文件、主文件名与目录名不一致，或目录内出现多个 `*.tn-mindmap.md` 时，均视为无效作品目录并提示结构错误。
- 支持直接读取与保存作品目录内的脑图文件；目录句柄可存入 IndexedDB，后续访问时按浏览器权限状态重新申请授权。
- 粘贴图片时在当前作品目录创建 / 使用 `assets/`，把图片写入本地文件，并在 Markdown 中保存相对路径。
- 需要新增资源解析层：相对图片路径必须通过工作区句柄读取为 Blob 后再提供给视图，不能直接按网站 URL 加载。
- 需要考虑外部文件变更与保存冲突；页面重新获得焦点或手动刷新时重新扫描，保存前校验文件是否已被外部修改。
- 工作区 API 不可用时保留“打开单个文件 + 下载导出”的降级路径。

### 1.5 PWA 与离线能力（已确认，后续实现）

- 应用支持安装为 PWA，并能在无网络时启动和使用核心编辑功能。
- 工作区句柄与本地草稿跨会话恢复；重新进入时仍需遵守 Chrome 返回的实际权限状态。
- 工作区 `assets/` 内的资源通过本地目录读取，可离线使用；仅引用远程 URL 的图片不承诺离线可用。
- PWA 仍是纯静态前端，不引入账号、云同步或服务端存储。
- PWA 属于 Web 应用层后续事项，不得阻塞当前桌面端编辑交互验收；工作区即使最终不实现，也不影响编辑器验收。

### 3.1 脑图交互与布局第一轮对齐（2026-08-18）

- **链接：** Canvas 按实际文字 run 精确命中链接，不再把整个节点误判为链接；hover 约 380ms 后在链接下方显示 URL、编辑和移除浮层，指针进入浮层不会因离开 Canvas 立即关闭；单击链接通过协议白名单在安全新标签页打开。
- **导航：** ↑ / ↓ 优先选择同一父级的上一 / 下一主题，跨出同级后才按画布几何位置兜底，因此一级主题可从“生活原则”直接向下切到“工作原则”。
- **框选与平移：** 空白区域直接拖拽为矩形框选；只有按住 Space 再拖拽才平移画布。Cmd/Ctrl+点击支持离散增减选择，多选工具栏提供粗体、斜体、下划线、删除线、高亮、待办、复制、清除样式和删除，复合操作只写一条历史。
- **编辑覆盖层：** Canvas 编辑态已改为受控 `contenteditable`，复用 raw-first segments，粗体 / 斜体 / 下划线 / 删除线 / 高亮 / 代码 / 链接在编辑时仍保持视觉样式；覆盖层位置、宽高、padding、字号和层级样式与 Canvas box 对齐，双击不再发生轻微位移。
- **折叠控件：** 展开态的控件只在节点 hover 时出现，为圆环内 `<`；折叠态常驻圆环内全部后代数量，而不是直接子节点数量。根节点仍允许折叠，这是项目刻意保留的增强能力。
- **父子相对布局：** 不再按全局深度强制所有主题共享固定横坐标。每组兄弟主题只对齐到自己的父主题右侧，父子间保持紧凑固定间距；短父主题的后代会自然靠近，长父主题只推动自己的后代，不影响其它分支。有子级主题仍以 220px 为宽度上限，叶子可扩展到 500px；编辑框沿用同一宽度策略，长文案进入 / 退出编辑不会让旁支横向跳动。
- **节点拖动预览：** 拖动过程中不提前修改文档树；被拖主题及其完整子树仍在原布局位置，以低透明度和蓝色虚线框作为占位。指针下只绘制被拖主题的浮动副本，并用错位双层边框区分真实节点；命中候选父主题、同级前插或后插时，同时强调落点并从预期父主题绘制临时折线到浮动副本。父主题右侧有限空白走廊也会持续识别为下级落点，松手后才写入一次移动历史。
- **进入主题：** 脑图支持 Cmd/Ctrl+] 或头部聚焦按钮进入任意已选节点；进入已折叠节点会自动展开，面包屑返回上级，根节点聚焦 / 折叠能力保持可用。
- **层级 UI：** 根节点、一级、二级、三级及以后使用分级字体、字重、填充和边框；一级节点使用灰底主题块，二级与更深层级更轻，任务、链接与图片语义仍独立呈现。
- **行内序列化：** 批量样式不再按每个 run 独立拼接标记，而按连续样式区间共享外层标记；粗体与斜体、删除线等跨片段组合不会再产生 `*****` 标记汤，解析与回写稳定往返。
- 自动测试覆盖父子相对横坐标、分支局部稳定性、长节点折行、层级 UI、全部后代统计、hover 折叠命中、精确链接命中 / 浮层、同级方向键、框选、Space 平移、Cmd/Ctrl 离散多选与批量格式、进入主题、富文本覆盖层和链接安全跳转。

- **编辑态画布变换：** Canvas 节点与 DOM 富文本覆盖层现在统一从 world 坐标投影到 screen 坐标；滚轮 / 触控板平移、缩放和重新布局都会同步编辑框与右侧 `+`，不会再因覆盖层停留在旧位置而看见两个相同节点。
- **节点右侧控件：** 选中或编辑状态优先显示 `+`，用于直接新增并编辑下级主题；普通 hover 有子节点且处于展开状态的主题时显示圆环 `<` 收起控件；折叠状态显示圆环内全部后代数量，而不是只统计直接子节点。
- **底部工具栏：** 单选与多选节点都会默认在画布底部居中显示操作工具栏；单选提供当前主题格式与结构入口，多选提供可批量作用的格式、复制与删除等操作。
- **快速折叠：** 头部 `CollapseMenu.vue` 提供“全部主题 / 1 级主题 / 2 级主题 / 3 级主题”。层级始终相对于当前 `focusRootNode`：当前进入的主题视为根，1 级是其直接子主题；“全部主题”递归折叠 / 展开当前聚焦子树。快捷键为 Cmd/Ctrl+Alt+1/2/3，以及 Cmd/Ctrl+Alt+Shift+`.` 切换全部主题。
- **右键菜单：** `CanvasContextMenu.vue` 区分单选与多选。单选支持插入同级 / 下级 / 上级主题、复制、剪切、粘贴、创建副本、仅删除当前主题、删除当前主题及下级主题、展开 / 折叠同级主题、进入此主题；多选只保留复制、剪切、删除所选主题及下级主题、展开 / 折叠同级主题。右键未选中节点时先切换为单选，右键当前多选集合时保留多选。
- **仅删当前主题：** 会话层 `removeNodeOnly` 删除主题自身，并把它的直接子主题原位提升到其父主题下；根主题和当前聚焦根主题受保护，整个动作只产生一条撤销历史。
- **搜索与替换：** 脑图不单独渲染搜索结果；从脑图触发 Cmd/Ctrl+F 或搜索入口时自动切换到大纲搜索结果视图。结果节点继续复用可编辑富文本面板，并支持上一处、下一处、替换和全部替换；替换会保留未命中部分的链接与行内格式，全部替换只写一条撤销历史。
- **深层主题导航：** `focusNode` 会从目标节点重建完整真实祖先链，不再把访问历史误当路径；`@tnotesjs/ui` 的 `FocusBreadcrumbs` 完整显示“全部 / … / 当前主题”，悬停任一级列出该层全部兄弟节点，按节点 ID 精确切换重名主题。路径无层数上限、保持单行，溢出时自动横向滚到当前项；同深度切换也会清理旧大纲草稿、选区与滚动状态。

## 6. 已知坑

1. **命中坐标**：必须相对 `.outline-spacer`；漏算 `.outline-view` padding-top（12）与 `.outline-title` margin-bottom（8）会导致落点偏一行。
2. **拖拽与 Vue 重渲染**：pointerdown 立刻写 `drag` 会换掉 grip DOM，监听/capture 丢失；阈值前只用闭包 `pending`。
3. **合成 PointerEvent 自测**：`isTrusted === false` 时放宽 pointerId；move 后偶发需短暂等待再读 DOM。真机拖拽最可靠。
4. **双监听**：不要同时在 grip 与 document 上各挂一份 move（会双触发）；以 document +（可选）setPointerCapture 为准。
5. **HMR**：改 `OutlineView.vue` 后若拖拽异常，硬刷新再测；历史上出现过 Invalid end tag / 递归更新导致模块未热更成功。
6. **富文本 DOM 不是持久化数据**：`RichInlineEditor` 的 DOM 只呈现由 raw 解析出的扁平 runs；普通输入必须走 `replaceInlineRange`，IME 只在组合期间允许浏览器临时改 DOM，结束后立即规范化。不要反向保存 `innerHTML`，也不要绕过纯文本 offset 映射直接拼 Markdown。
7. **行内解析器不是完整 CommonMark**：本轮覆盖项目明确方言、嵌套常见格式和简单 URL；若未来要求括号 URL、复杂转义或任意 HTML，应先扩展行内 CST 与测试，而不是在 Vue 中拼字符串。
